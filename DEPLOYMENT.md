# Owner workspace release

## What ships

- Home page Owner Login and Request Information links.
- Owner sign-in using email, a scrypt password hash, and a TOTP authenticator.
- Server-side opaque sessions (30-minute expiry), HttpOnly/SameSite cookies, origin checks, CSRF-protected logout, database-backed rate limits and authenticator replay prevention.
- Owner-only application listing, latest 100 records and total count.
- Public contact requests with explicit consent, validation and duplicate-retry protection.
- Empty quote/commission sections that do not fabricate carrier activity.

This is contact-request intake, not a complete insurance application. No live quoting, policy binding, customer account, agent assignment, payment, commission integration or email delivery exists yet.

## Build and verify

Use Node 24. Run `npm ci`, `npm run build`, `npm run check`, `npm test`.
Tests use an embedded PostgreSQL engine (PGlite), including database close/reopen persistence. These are not evidence of a successful managed Render Postgres deployment.

## Required hosting change

The current Render service is STATIC and copies only index.html. It cannot run this backend or serve the new owner/application pages under that old copy command.

Deploy the repository as a Node WEB SERVICE with a PostgreSQL database, in the same Render region. Build: `npm ci --include=dev && npm run build && npm run check && npm test`. Start: `npm start`. Health path: `/healthz`.

Private repository Git credentials must be linked in the intended Jim Hill Render workspace. Do not make the repository public as a workaround. This release does not claim that deployment is complete or automatic.

Set server environment:

- NODE_ENV=production
- DATABASE_URL: the managed database connection string, stored as a secret
- APP_ORIGIN: exact HTTPS origin of the web service, no trailing slash
- OWNER_EMAIL: the intended owner email
- OWNER_PASSWORD_HASH: generated locally using `python setup_owner.py`
- OWNER_TOTP_SECRET: generated by that same script and enrolled in the owner's authenticator
- APPLICATION_INTAKE_ENABLED=false initially; set true only after owner login and private database access are verified and intake is ready for real requests

No default owner password or production test credential exists. Missing owner configuration fails closed. Do not send passwords, database URLs, or authenticator secrets through chat or commit them.

The schema is created idempotently at startup for this first release. Future schema changes require ordered migrations and backward-compatible rollback. Production uses Postgres only; preview.mjs is local QA only and never used by npm start.

## Launch verification still required

Confirm managed Postgres connectivity, private network and backup configuration, owner authenticator enrollment, secure cookies, anonymous denial, a synthetic submitted request appearing after login, logout, and persistence across a real service restart. Remove test submissions through an approved administrative maintenance process. Review the contact notice, retention policy and support process before collecting real people’s data.

Production owner login and submission flows have automated integration coverage but still need browser acceptance against the deployed service. MFA provisioning/recovery is administrator-assisted; role management, account recovery UI and an immutable audit history are later backlog items.
